# 低温冷却管网 · 巡检路线审计

无向图**中国邮递员问题（Chinese Postman Problem）**的精确求解与可视化审计：

- 在每条管段至少走一次的基础上，选择**额外重复管段集合**使各节点度数全为偶数，
  且**增加长度最小**（最小 T-join）；
- **精确给出全部同优（最低增程）集合的数量**，而不是完美匹配数——
  同一 T-join 边集可对应多个匹配（如星形 K1,3 的 3 个匹配对应同一个边集），
  本系统按边集去重计数；
- 按管段标识 ASCII 顺序、**0 优先位向量**确定唯一规范集合；
- 依据全部同优集合，把每条管段标为 **必重复 / 可重复 / 从不重复**；
- 为规范集合生成一条从**检修口出发并回到检修口**、逐步可核对、
  恰好使用「原管段 1 份 + 重复副本 1 份」的确定性闭合欧拉路线；
- 页面编辑（2–18 个唯一 ASCII 节点、1–32 条正整数长度无向管段，
  允许平行边、禁止自环）、选择检修口、发起审计；
- 断连、未知端点、重复标识、非法长度、不存在的检修口等错误
  **在页面对应行/字段定位**；失败保留输入并清除旧结论；
- 成功后管网图、分类表、逐步路线**联动**：点选管段即高亮它在路线中的全部经过位置。

纯 Python 标准库实现（后端 + 测试零第三方依赖）。

## 算法

对全部 2^m（m≤32）个 0/1 重复向量，要求每个奇度点被奇数条重复边覆盖、
其余节点被偶数条覆盖（全节点综合症空间），并最小化重复长度。

边按标识顺序均分为 4 组（每组 ≤8 条）：

1. 组内枚举 2^k 种选择，按节点奇偶综合症聚合最小费用；
2. 聚合同时携带：精确同优集合数（大整数计数）、
   各边位在所有同优集合中的与掩码 / 或掩码（推出必/可/从不）、
   组内 0 优先字典序最优代表；
3. 组间做综合症 XOR 卷积，仅在目标综合症合并；
4. 规范集合 = 所有同优集合中位向量（首位权重最高）数值最小者；
5. 对「原管段 + 重复副本」的欧拉多重图做确定性 Hierholzer。

32 边规模求解约 0.03 秒（本机实测）。

## 运行

```bash
# 构建并启动页面与健康检查服务（宿主机端口可用 HOST_PORT 配置，默认 8080）
docker compose up -d --build
# 自定义宿主机端口
HOST_PORT=9000 docker compose up -d --build

# 健康检查
curl http://localhost:8080/healthz
# 打开 http://localhost:8080/
```

## verify 单次校验服务

核对①奇度管网的同优分类、②欧拉管网的零增程边界、③代码测试、
④构建完整性、⑤HTTP 冒烟，随后退出，用退出码报告结果（0 全部通过）：

```bash
docker compose --profile verify run --rm verify
echo $?
```

也可不经过容器在本机运行：

```bash
python3 -m unittest discover -s tests -v          # 仅代码测试
PORT=8000 python3 -m app.server &                  # 启动服务
WEB_URL=http://127.0.0.1:8000 python3 -m app.verify
```

## 目录

```
app/cpp.py        精确求解（综合症分组卷积、计数/分类/规范集、欧拉路线）
app/validate.py   全部输入校验与可定位错误
app/server.py     标准库 HTTP 服务（/、/healthz、/api/audit）
app/verify.py     单次校验服务（退出码报告）
app/static/       单页前端（编辑、错误定位、SVG 管网图与路线联动）
tests/            unittest：随机图 2^m 暴力对照、路线逐步合法性、校验与 HTTP
Dockerfile, docker-compose.yml
```
